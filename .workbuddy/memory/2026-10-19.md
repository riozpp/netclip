# 2026-10-19

## NetClip：hellotik / kukutool 复刻 + Cloudflare 部署

- REA 两个目标站：`www.hellotik.app/zh`、`dy.kukutool.com`。二者共用同一 WAF（响应头 `Server: wafcdn`，返回 39 字节的 `<script src="/_guard/auto.js">` 挑战页），curl / Playwright 均无法取得应用层 HTML，最终通过具备 JS 渲染的抓取通道拿到正文与标题。报告见 `docs/rea-report.md`。
- 结论：两站是同一产品模板的两个马甲（Hero + 卖点 + 流程 + FAQ + 页脚），功能 = 多平台短视频/图文去水印下载；B 站额外暴露了「每日免费额度 + 验证码 + 登录提额」的风控三段式。
- 复刻为独立实现 `netclip`：Cloudflare Workers 单入口 + `[assets]` 静态绑定，零构建。
  - `src/index.js` 路由/限流/错误出口，`src/proxy.js` 媒体流式代理（域名白名单 + Referer 映射 + Range 透传），`src/resolvers/index.js` 五平台解析器。
  - 前端两套皮肤：`public/index.html`（浅色中文，可切英文）+ `public/kuku.html`（深色英文），共享 `styles.css` / `app.js`，`pro.css` 做主题覆盖。
- 已上线：https://netclip.riozpp.workers.dev （GitHub `riozpp/netclip`，Actions 自动发布，secrets 已写入 CLOUDFLARE_API_TOKEN / CLOUDFLARE_ACCOUNT_ID）。

## 环境坑位（重要，后续复用）

- 沙箱所有外网请求走本地代理 `127.0.0.1:57813`；curl 访问 localhost 必须 `--noproxy '*'`。
- Playwright 必须显式 `proxy: { server: 'http://127.0.0.1:57813' }`，否则 ERR_CONNECTION_RESET。
- `wrangler dev` 在本沙箱能监听端口但不回包，本地验证改用「直接 import `src/index.js` 并手工构造 Request」的用例脚本（`scripts/test-worker.mjs`）。
- `*.workers.dev` 在本机被 DNS 污染（解析到 199.59.149.201），无法直连验证；改用 GitHub Actions 流水线结果 + Cloudflare 版本 API 作为部署证据。
